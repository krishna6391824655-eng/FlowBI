# Free deployment setup

This project uses Vercel for the Vite frontend, Render for the FastAPI backend, and an external PostgreSQL database. The frontend and API are separate services, so configure their public URLs in the environment variables below.

## 1. Create a PostgreSQL database

Create a PostgreSQL database with a provider whose free tier allows ongoing use, and copy its **pooled** connection string if one is offered. Keep the password private. Use the provider's SQLAlchemy/psycopg2-compatible URL, beginning with `postgresql://` or `postgresql+psycopg2://`.

## 2. Deploy the backend to Render

1. Import this Git repository in Render as a Blueprint. Render will find `render.yaml` and create the `flowbi-api` web service.
2. Set `DATABASE_URL` to the database connection string.
3. Once the frontend is deployed, set `CORS_ORIGINS` and `FRONTEND_URL` to its exact HTTPS origin, for example `https://your-project.vercel.app` (no trailing slash). Add any Vercel preview/custom domains you will use as comma-separated CORS origins.
4. `JWT_SECRET_KEY` is generated by the Blueprint. Keep it private and stable; changing it signs users out.
5. `GROQ_API_KEY` enables AI insights. `RESEND_API_KEY` and `MAIL_FROM` enable password-reset emails and require a verified sender. These are optional for basic login, upload, and pipeline features.
6. Wait for the service to become Live. Verify `https://<your-render-service>.onrender.com/health` returns `{"status":"ok"}`.

## 3. Deploy the frontend to Vercel

1. Import the same repository as a Vercel project.
2. Set the project **Root Directory** to `Dataflow` and leave the Vite build settings detected from `package.json` (`npm run build`, output `dist`). `Dataflow/vercel.json` sends client-side routes back to the SPA.
3. Add `VITE_API_URL` as an environment variable for Production (and Preview if needed), with the backend origin, for example `https://<your-render-service>.onrender.com`. Do not add `/api` or a trailing slash.
4. Deploy. Copy the resulting Vercel origin into Render's `CORS_ORIGINS` and `FRONTEND_URL`, then redeploy the backend if Render requests it.

## Free-tier behavior

Render's free web service sleeps after 15 minutes without traffic; its next request can take about a minute to wake it. Its filesystem is temporary, so the app must use PostgreSQL rather than SQLite in production. Avoid Render's free PostgreSQL for real user data: Render documents a 30-day expiration for that tier. Free database limits at other providers can change; check the provider's current retention, connection, storage, and backup terms before relying on it.

## Local production build

In `Dataflow`, set `VITE_API_URL` to the backend URL and run `npm run build`. Never put database credentials, JWT keys, or provider API keys in `VITE_*` variables; those are included in browser code.
